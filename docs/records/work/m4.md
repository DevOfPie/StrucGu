# M4 — The two optional modules

**Depends on:** [M2](m2.md). Ordering preference only against [M3](m3.md) —
these do not depend on the base modules, but writing them second tests whether
the contract survives an obligation that is not base.

**Discharges:** the README's module table listing two modules that do not exist.

`work-units` and `investigations`. Both are things LinkCtrl does well and
neither is something a repository is broken without, which is what makes them
the test of whether "optional" is a real state or a label.

## Done means

- Both modules have all six artifacts.
- Both carry `base: false`, and no check in either is reachable from a base
  module's prerequisites.
- No obligation in either assumes code, tests, a build, releases, or CI.
- "Milestone", "phase", and "ADR" appear nowhere as mandated names — only as
  examples of what a role may be called locally.
- `work-units` preserves the field that names the promise a unit closes, because
  it is what keeps a scope contract from accumulating rows nothing ever
  discharges.
- `work-units` requires that rules common to every unit are stated once in an
  index, and the check for it names what goes wrong otherwise rather than
  asserting the rule.
- `investigations` requires that a record states what it was verified against,
  not merely that it was verified.
- Deliberately not done: neither module checks whether the *content* of a
  falsifiable claim is actually falsifiable. That is judgment and is declared as
  such rather than approximated by a pattern.

## Risks

`work-units` is the module most likely to collide with an existing project, because
almost every repository already has an issue tracker playing part of this role
and a strong opinion about it. If the role map cannot express "the tracker plays
this role", the module is unusable outside repositories that keep work units as
files — and the checks are written against files. This may be the first module
an objection is filed against, which is the intended outcome rather than a
failure.
