# M12 — F1 and F2 are closed by use rather than by review

**Depends on:** [M10](m10.md), [M11](m11.md). Closing these before an
implementation and a second adopter exist would be deciding them from the same
chair that opened them.
**Discharges:** both open rows in [findings.md](../findings.md), which have been
unreviewed since before the self-walk.

`F1` and `F2` were recorded during phase one and neither was produced by a
check — both are observations about the catalog's own construction that no check
here can see. `F2` is the one that matters: `role_referenced` resolves markdown
links only, while the obligation it serves reads as though it catches a record
naming its destination in prose. The check is narrower than its obligation, and
it is the highest-value check in the catalog.

## Done means

- `F1` is closed. The what-breaks-without-it argument for the base set has one
  normative home and the other location links to it. Which one is normative is
  argued in [decisions.md](../decisions.md), because two prose statements that
  must agree and cannot be checked will eventually disagree.
- `F2` is closed as exactly one of:
  - the obligation is **reworded** to say what the check actually does, and a
    fixture is added in which the destination is named in prose and the check
    correctly reports `ok` — turning a silent coverage gap into a stated
    limitation; or
  - a **new check kind** is added that matches a path-shaped string anywhere in
    the target, with its fixture and its false positives documented under
    [SPEC.md](../../../SPEC.md) "Known false positives".
- Whichever is chosen, the reasoning is a dated entry in
  [decisions.md](../decisions.md) naming the option not taken and what it would
  have cost.
- Each closed row moves to the `Closed` section of
  [findings.md](../findings.md) with its disposition. The row is not deleted —
  the queue is a record, and a queue that empties by deletion cannot show what
  it caught.
- Any finding raised by [M10](m10.md) or [M11](m11.md) that is real but not this
  unit's scope is a new row in [findings.md](../findings.md) rather than work
  absorbed here. This unit is as good a place as any to fail that rule, which is
  why it is written down.
- Deliberately not done: no other check is revisited on suspicion. A check
  nobody has watched produce a wrong answer is a check with no evidence against
  it, and rewriting it on taste is how a specification acquires churn that reads
  like progress.

## Risks

The recommendation on `F2` is the first option, and the argument is in
[SPEC.md](../../../SPEC.md) already: a check matching path-shaped strings in
prose fires on every document that quotes a path, and a check that produces
noise gets made non-required within the hour and then nobody looks at it again.
That reasoning is the spec's own, applied to itself. It is also convenient —
option one is cheaper — so the entry should name that and say why the argument
holds anyway.

Adding a check is a **major** version whichever way `F2` goes if option two is
taken, per [SPEC.md](../../../SPEC.md) "Versioning". That constraint is what
makes this a real decision rather than a preference, and it must not be
discovered after the work is done.
