# M12 — F1 and F2 are closed, F2 by use rather than by review

**Depends on:** [M10](m10.md), [M11](m11.md) — **for `F2` only.** `F1` depends on
nothing, could be closed today, and is scheduled here as an *ordering
preference* so both rows move together. A soft edge presented as a hard one
hides a scheduling choice, and this one was presented that way when the unit was
first written.
**Discharges:** both open rows in [findings.md](../findings.md), which have been
unreviewed since before the self-walk.

`F1` and `F2` were recorded during phase one and neither was produced by a
check — both are observations about the catalog's own construction that no check
here can see. `F2` is the one that matters: `role_referenced` resolves markdown
links only, while the obligation it serves reads as though it catches a record
naming its destination in prose. The check is narrower than its obligation, and
it is the highest-value check in the catalog.

## Done means

- `F1` is closed. The what-breaks-without-it argument for the base set has one
  normative home and the other location links to it. Which one is normative is
  argued in [decisions.md](../decisions.md), because two prose statements that
  must agree and cannot be checked will eventually disagree.
- `F2` is closed as exactly one of:
  - the obligation is **reworded** to say what the check actually does, and a
    fixture is added in which the destination is named in prose and the check
    correctly reports `ok` — turning a silent coverage gap into a stated
    limitation; or
  - a **new check kind** is added that matches a path-shaped string anywhere in
    the target, with its fixture and its false positives documented under
    [SPEC.md](../../../SPEC.md) "Known false positives".
- **Whichever is chosen, [SPEC.md](../../../SPEC.md) changes and this unit says
  how.** Option one adds a fixture tree that is neither `satisfies/` nor
  `violates-<CHECK-ID>/`, which the module contract's "exactly these" does not
  currently admit; option two adds a check kind to a closed vocabulary. Both are
  edits to the specification, in scope for this phase, and named before the work
  starts rather than discovered during it.
- The version bump follows the rule and is stated with the choice: option one is
  a **minor** — a check narrowed, nothing a clean adopter newly sees. Option two
  adds a check and is therefore a **major**, per
  [SPEC.md](../../../SPEC.md) "Versioning" and
  [decisions.md](../decisions.md#a-new-check-never-ships-in-a-minor-version).
- **The reasoning is recorded when the choice is made, not before.** A dated
  entry in [decisions.md](../decisions.md) names the option taken, the option
  not taken, and what that one would have cost. This record deliberately states
  no recommendation: an earlier version argued the case for option one in
  advance, in a unit whose whole point is that the choice waits for evidence.
- Each closed row moves to the `Closed` section of
  [findings.md](../findings.md) with its disposition. The row is not deleted —
  the queue is a record, and a queue that empties by deletion cannot show what
  it caught.
- Any finding raised by [M10](m10.md) or [M11](m11.md) that is real but not this
  unit's scope is a new row in [findings.md](../findings.md) rather than work
  absorbed here. This unit is as good a place as any to fail that rule, which is
  why it is written down.
- Deliberately not done: no other check is revisited on suspicion. A check
  nobody has watched produce a wrong answer is a check with no evidence against
  it, and rewriting it on taste is how a specification acquires churn that reads
  like progress.

## Risks

The cheaper option is also the one with the stronger argument available to it,
which is exactly the condition under which a decision gets made on cost and
justified on principle afterwards. The defence is the ordering: `F2` is closed
after [M10](m10.md) and [M11](m11.md) have produced real instances of the
check's behaviour, and the decision entry has to name what the rejected option
would have cost. If the entry cannot name a cost, the decision was taken on
convenience.

`F1` closing early is the smaller risk and the likelier one to be skipped. It is
a prose-agreement problem no check can see, which means nothing will ever remind
anyone it is open except this row.
