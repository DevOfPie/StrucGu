# M19 — Three records are corrected once the expectations have settled

**Depends on:** [M16](m16.md), [M17](m17.md) and [M18](m18.md), all hard. Each of
these three findings is about a record that those units are going to move.
**Discharges:** `F3`, `F15` and `F18` in [findings.md](../findings.md).

These were the obvious things to fix first and they are deliberately last. Fixing
them before the measurement units would mean fixing them twice: `M16` adds trees
to modules whose prose counts them, `M17` changes the schema the implementer's
guide describes, and `M17` bumps every module past the version this repository's
own adoption record pins.

## Done means

- **`F3`** — `triage-rule`'s `expected.md` states a judgment-line count matching
  no reading of its own fixtures. The prose agrees with
  [expected.yaml](../../../modules/triage-rule/fixtures/expected.yaml) **as that
  file stands after [M16](m16.md)**, or states why it counts differently.
  `expected.yaml` is not edited to match the prose: the conformance criterion is
  measured against the data file, and moving the measured side to fit an unmeasured
  one inverts which file is authoritative.
- **`F15`** — [auditing.md](../../auditing.md) lists a module's `fixtures/`
  directory without `expected.yaml`, required since [M8](m8.md). The listing is
  complete **and reflects whatever [M17](m17.md) added to that file**, and the
  sentence sending an implementer to the prose file sends them to the data file
  instead.
- **`F18`** — the five pins in [strucgu.yaml](../../../strucgu.yaml) name the
  versions the modules actually ship at the end of this phase, each with a dated
  comment naming the review that moved it. The fixture-tree pins under
  `modules/*/fixtures/` do **not** move, and the unit records that this was
  checked rather than assumed —
  [that argument](../decisions.md#the-modules-bump-to-020-and-no-adoption-record-moves-with-them)
  names the fixture trees specifically, which is why `F18` existed at all.
- The self-walk is re-run after the pins move and the drift notices are gone. If a
  check result moves as a consequence, the unit **stops and says so**: a pin does
  not constrain what runs, so a moved result means something else was wrong.
- **The reopening question is answered on the record.** `F3` and `F15` both trace
  to [M8](m8.md) — one is its prose half left behind, the other the adopter-facing
  guide it did not update. Whether that makes M8's claim false and
  [reopens it](../triage.md), or whether M8's claim stands and these are
  corrections beside it, is this unit's judgment and is argued in
  [decisions.md](../decisions.md).
- All three rows move to *Closed*. Nothing is closed by being deleted.

## Risks

The reopening judgment is the risk, and it is a rule being used for the first
time. Reopening too readily makes the status table churn and turns every prose
defect into a unit that was never finished; reopening too reluctantly leaves
`done` rows asserting things this repository has already written down as false,
which is the outcome the rule exists to prevent. The unit has to pick, and the
argument it records is worth more than the pick.

`F3` carries a smaller trap that this unit's position in the phase makes worse.
The count in the prose file is wrong, and after [M16](m16.md) it will be wrong by
a different amount. The temptation is to make the number agree without asking
which reading it was ever counting. A number changed to end a disagreement is the
same class of defect as the one being closed.
