# M15 — A bump sized by what an implementer must re-do

**Depends on:** nothing.
**Discharges:** `F16` in [findings.md](../findings.md). It also unblocks
[M16](m16.md) and [M17](m17.md), which is the reason it is first among the
measurement units rather than last.

[SPEC.md](../../../SPEC.md#versioning) sizes a module's version by what a
previously clean **adopter** will newly see. An adopter and an implementer are not
the same reader, and this repository has already published a release where they
disagreed: `decision-log` `0.3.0` corrected five `DL-03` fixture rows from `ok` to
`skip`, changed no check, no obligation and no role, correctly stated that an
adopter newly sees nothing — and invalidated every row of the only conformance
claim in existence.

## Done means

- [SPEC.md](../../../SPEC.md#versioning) answers, for a change that moves what a
  conformant run must output while an adopter sees nothing, which bump it takes
  and why. Either a row sized by what an **implementer** must re-do, or an
  explicit statement that an implementer re-runs on every bump and version numbers
  do not carry that signal. Both are answers; silence is not.
- The answer is reconciled with [conformance.md](../../conformance.md)'s clause 5,
  which already states the consequence — *a new check makes a prior claim stale,
  not false* — and with its closing observation that the two readers differ. If
  the resolution contradicts that clause, the clause moves and the unit says so.
- The rule is stated where a version is decided, not only where conformance is
  described. A reader bumping a module reads the versioning table and nothing
  else.
- The two versioning rules that
  [already disagree by design](../decisions.md#the-two-versioning-rules-measure-different-readers-and-the-conflict-is-reported-rather-than-picked)
  — SPEC.md sizing a module, [CHANGELOG.md](../../../CHANGELOG.md) sizing the
  repository — are not collapsed into one. This unit adds a reader, not a
  reconciliation. If the outcome is three rules measuring three readers, the unit
  says so plainly rather than presenting it as tidy.
- `F16` moves to *Closed* with its disposition.

## Risks

The trap is generalising from one instance. `F16` has exactly one worked example,
and a versioning rule written to describe it will fit it perfectly and may fit
nothing else. The defence is that the rule has to be stated in terms of what makes
a claim stale, not in terms of fixture corrections specifically — the next
instance will not be a fixture correction.

The second risk is the phase's own ordering. [M16](m16.md) and [M17](m17.md) both
rewrite expectation rows in bulk, which is precisely the change class this unit
sizes. Shipping them first would mean deciding the rule while standing on the
largest instance of it, and this repository has already recorded once that a
criterion assembled around a reference implementation is the failure mode to
avoid.
