# M20 — The release is walked, and what moved is stated for an implementer

**Depends on:** [M16](m16.md), [M17](m17.md), [M18](m18.md) and [M19](m19.md),
all hard. There is nothing to release until they have landed.
**Discharges:** nothing in the queue. It exists because [M21](m21.md) needs a
released version to adopt, and because a phase that changes the contract and does
not publish what changed leaves every implementer to diff it.

Phase two ended this way and this unit is its equivalent. What is different is
the audience: `0.2.0` was breaking for an implementer and said so in prose, and
this release is the first to be sized by the rule [M15](m15.md) writes.

## Done means

- Every gate in [triage.md](../triage.md) "Before a release is tagged" over the
  whole repository, not the changed files, and the repeat-from-step-one rule
  honoured if the walk triggers work.
- **The walk is committed as a third file**, beside
  [self-walk.md](../self-walk.md) and [self-walk-0.2.0.md](../self-walk-0.2.0.md)
  rather than over either. The diff between walks is the only thing here that
  shows movement, and this is the first walk where the fixture count itself moved.
- **The version is sized by [M15](m15.md)'s rule and this is its first use.** If
  the new rule and the two existing ones disagree, the disagreement is reported
  rather than resolved by picking, per the standing answer on
  [the two rules that already measure different readers](../decisions.md#the-two-versioning-rules-measure-different-readers-and-the-conflict-is-reported-rather-than-picked).
- [CHANGELOG.md](../../../CHANGELOG.md) says what an **implementer** must re-read
  and re-run, separately from what an adopter newly sees. Those are different
  lists this time and the entry does not merge them.
- [README.md](../../../README.md) "What 0.x means here" is rewritten against what
  this phase actually measured: how many normative statements had no tree, how
  many now do, how many survive with none, and what the deliberate-breakage
  re-measurement returned. **If the breakage number did not improve, it leads.**
- The documentation pass runs over every file, including
  [conformance.md](../../conformance.md), whose *what a claim cannot cover* table
  is the thing [M16](m16.md) spent the phase shortening. A table that still lists
  something now pinned is a failing gate.
- **The repository is not tagged by this unit.** Tagging is the owner's action,
  for the reason [M7](m7.md) gives and [M13](m13.md) repeats.

## Risks

The phase's own results are the risk. This release can be read as the catalog
becoming trustworthy, and what it actually is is a catalog that has measured how
much of itself was untested and found the answer embarrassing. The `0.x` section
has to carry that without either apologising or flattering, and it is the third
release in a row where the honest number is the unflattering one.

A second risk is quieter. This is the first release whose changelog has two
audiences with different lists, and the temptation is to write one list and label
it twice. An adopter who reads an implementer's list concludes their repository
needs work it does not need.
