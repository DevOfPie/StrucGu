# M2 — The module contract

**Depends on:** [M1](m1.md).
**Discharges:** modules having no defined shape, and checks having no defined
meaning across independent implementations.

Everything in the catalog is downstream of this file. With no runner shipping,
the specification is the only thing that makes two implementations agree, so it
has to be written before there is anything to describe.

## Done means

- [SPEC.md](../../../SPEC.md) defines the vocabulary as a table, one line per
  term, in the style of the triage file.
- It defines every manifest field, and nothing it defines is unused by any
  module.
- The check vocabulary is closed and each kind states what it observes, what
  counts as a pass, and what its known false positives are.
- It states that there is no shell escape hatch and why: a manifest that can
  carry an executable string makes adopting a module arbitrary code execution.
- It distinguishes declaration checks from behaviour checks and states which
  rule applies to each.
- It states that prose is normative and the manifest is convenience, and that a
  disagreement between them is a bug to report rather than resolve.
- It states that a disagreement between two correct-looking checkers is a
  missing fixture, not a checker defect.
- It defines the five output states and states that `skip` never folds into
  `ok`.
- It defines remediation permissions and prohibitions, including that content is
  never moved out of an append-only record.
- It defines version bumps by what a previously clean adopter newly sees, and
  states that a new check is always major.
- It carries a worked example that is deliberately **not** one of the five
  modules, so the specification is not a description of its only instance.
- No banned word appears in the file.

## Risks

The check vocabulary is being designed before any obligation has been written
against it, so it is likely to be wrong in ways only contact will reveal.
Widening it before adopters exist is cheap; widening it after is a change every
adopter inherits. The mitigation is ordering — M3 writes real obligations
immediately, and any gap found there is fixed here rather than worked around.
