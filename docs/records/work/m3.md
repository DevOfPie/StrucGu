# M3 — The three base modules

**Depends on:** [M2](m2.md).
**Discharges:** the base set named in the README having nothing behind it.

`triage-rule`, `decision-log`, `findings-queue`. These are the three whose
absence breaks something specific, so they are the three that get written first
and the three the rest of the catalog is allowed to depend on.

## Done means

- Each module has all six artifacts: README, `module.md`, `module.yaml`,
  `CHANGELOG.md`, `templates/`, `fixtures/`.
- Every obligation traces to a named LinkCtrl artifact with a `file:line`, or is
  explicitly marked as newly invented.
- Every obligation is satisfiable by StrucGu's own [M1](m1.md) records, and
  `module.md` names the file that satisfies it. An obligation StrucGu cannot
  meet with no code has smuggled in an assumption about a toolchain.
- `decision-log` ships both accepted forms — one growing file, and a directory
  of one file per decision — so a repository with existing decision records is
  configuring rather than deviating.
- `findings-queue` declares `triage-rule` as a prerequisite, and the
  prerequisite is stated in the manifest rather than only in prose.
- Each README states at least three concrete costs, names who should **not**
  adopt it, carries the one-line exit instruction, and says plainly that none of
  this makes software work.
- `findings-queue`'s README carries the docs-site publication warning in bold: a
  repository that globs its docs directory into a static site generator will
  publish its internal findings queue to the public web.
- `decision-log`'s README names the append-only conflict with tools that rewrite
  a superseded record in place, as a legitimate deviation rather than something
  an adopter discovers as a failure.
- Every check has an id of the form `XX-NN` and appears in both `module.md` and
  `module.yaml` with the same meaning.

## Risks

The obligations are generalised from one repository plus this one. Two instances
is barely enough to tell a general convention from one project's habit, and the
naming divergence between them is the only thing currently testing whether the
role layer is real. Expect the first outside adopter to find an obligation that
encodes a LinkCtrl assumption nobody noticed.
