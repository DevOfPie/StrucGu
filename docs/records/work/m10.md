# M10 — The first checker, written from the specification alone

**Depends on:** [M8](m8.md).
**Discharges:** [M6](m6.md)'s recorded weakest link — "a fixture written by the
same person who wrote the check tests the check against its author's
understanding of it ... the real test is the first independent checker".

Zero implementations of this specification exist. Every claim the catalog makes
about being implementable, language-neutral, and precise enough to build from is
untested. This is the unit that converts the largest open risk in the repository
into either evidence or a list of defects.

The independence here is partial. Why, and what it costs, is in
[decisions.md](../decisions.md#the-first-checker-is-whippys-and-its-independence-is-partial)
and in the corrections that follow it — not restated here.

## Done means

- A checker covering all five modules exists and reproduces every expectation in
  [M8](m8.md)'s files across all 33 fixture trees — check results and judgment
  entries both. **Or the reduced module list is recorded in this unit's index
  row before the unit closes**, because a `done` status over a partial checker
  is a false status.
- **It does not live in this repository.** No runner ships here — see
  [decisions.md](../decisions.md#there-is-no-runner-and-that-is-the-largest-single-decision-here).
  It lives in a repository of its own, named before the unit starts, and whether
  that repository is public is recorded with the name.
- **Separate repository does not make it not the reference implementation.**
  Location was never the operative variable; primacy is. This will be the only
  implementation in existence, commissioned by the catalog's owner, named in the
  catalog's records before it exists, and — with [M9](m9.md) deferred — the
  thing any eventual criterion is derived from. The second implementer will find
  it and read it. Separating the repository buys discoverability-by-adjacency
  and nothing more, and the record says so rather than claiming the problem
  away.
- **Its inputs are the normative surface only**: [SPEC.md](../../../SPEC.md),
  [modules/](../../../modules/), [adopting.md](../../adopting.md),
  [auditing.md](../../auditing.md), [objections.md](../../objections.md).
  **`docs/records/` is excluded**, this file included. These records state how
  the ambiguity list will be judged — that a thin one reads as suspicious, that
  low-confidence resolutions are counted — and an implementer who has read the
  scoring function produces the shape it rewards. The observer's notebook does
  not go to the subject.
- **The author does not answer questions about what a check means.** Every
  question the implementer has to ask is the deliverable, not an obstacle to it.
  Enforced by the owner declining. **Attested, not verifiable** — a kept rule
  and a broken one leave the same trace, and the honest place for that is here
  rather than among the falsifiable bullets.
- Each ambiguity is recorded with the check id, what was unclear, the readings
  available, the one taken, and how confident that choice was. **The log is
  committed to the checker repository one ambiguity per commit**, so that
  "recorded before resolving" is a claim its own history can settle rather than
  an assertion.
- Each recorded ambiguity is then resolved as exactly one of: a new fixture that
  pins the boundary, an obligation reworded, or a decline with reasoning. This
  is [SPEC.md](../../../SPEC.md) "Ambiguity is a missing fixture" run for the
  first time. **Fixture and obligation changes are edits to this repository's
  specification**, unbounded in number, and are in this phase's scope — see
  [work/README.md](README.md) "Not in this phase".
- The ambiguity list is written up under the `investigations` role, and
  [strucgu.yaml](../../../strucgu.yaml) maps that role instead of leaving it
  unmapped. The four `IN-*` checks stop reporting `skip` because a real
  investigation now exists — not because one was invented to exercise them. See
  [self-walk.md](../self-walk.md), where those four skips are described as the
  point of the walk, and [M13](m13.md), which records what the walk loses when
  they stop skipping.
- Deliberately not done: no second implementation. Two checkers disagreeing is
  the sharper test and it costs a second independent party; one is what this
  unit buys, and what it does not prove is stated in the record rather than
  implied away.

## Risks

**The shared-lineage risk is unmeasured in this phase, and the confidence field
does not measure it.** A reader from the same model family may reconstruct the
co-author's reading of an ambiguous check without ever noticing there was a fork
— which presents as *no perceived ambiguity, at high confidence*, and is
therefore indistinguishable in the record from a specification that was simply
clear. Confidence bounds only the ambiguity the implementer noticed. It catches
coin-flips; it cannot catch the fork nobody saw. That risk is discharged by a
future implementation from a different lineage and by nothing in this unit.

Independence is otherwise fragile in the ordinary way. If the implementer asks
and is answered, this unit produces dogfood with more steps, and the failure
would not be visible in the output, because a checker built with help still
passes the fixtures.

Reproducing the expectations proves the checker agrees with the fixtures, which
is a weaker claim than conforming to the specification. The two come apart
exactly where the fixtures under-determine a check — [F2](../findings.md) is
already a known instance — and that gap is what [M11](m11.md) is for. With
[M9](m9.md) deferred, "conforms" means only "reproduced the expectations" for the
duration of this unit, and that reduced meaning should be stated wherever the
result is reported.

This unit has no upper bound on effort. A checker covering five modules and 28
checks is a real project. If it is scoped down, scope it by **module**, not by
check — a checker covering three modules completely tells the truth about those
three, where one covering half of each tells the truth about nothing.
