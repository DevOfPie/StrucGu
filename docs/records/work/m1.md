# M1 — The repository states what it is, and its own records exist

**Depends on:** nothing.
**Discharges:** the repository having no stated posture, and having nowhere to
put the reasoning behind decisions made before any module exists.

Records come first. Every decision taken while building the catalog needs a home
at the moment it is taken, or the reasoning is reconstructed later from memory
and is wrong.

## Done means

- [README.md](../../../README.md) states the posture in the negative — no
  enforcement, no certification, no badge, no score, no adopter registry, no
  tool to install, findings rather than verdicts — before it describes anything
  the repository does.
- The README names five modules and does not imply a catalogue larger than what
  exists.
- The README states what 0.x means here, rather than leaving it to convention.
- [docs/records/](../) exists complete: triage, decisions, findings, and the
  work index with its template.
- [decisions.md](../decisions.md) already holds a dated entry for every choice
  made before any file was written: why the repository exists, five modules, the
  base set of three, spec-only with no runner, structure-not-content, adoption
  binding, remediation limits, self-application as dogfooding, the naming
  divergence, what is deliberately left out, versioning, and the objection loop.
- [triage.md](../triage.md) defines in spec and out of spec, states what happens
  on each side, links to the findings queue as the destination, and carries the
  precedence rule for two governing documents that disagree.
- StrucGu's record paths differ from LinkCtrl's, and
  [decisions.md](../decisions.md#strucgus-own-records-use-different-filenames-from-linkctrls)
  says why.
- Two licences exist and the split is stated: MIT for the specification, MIT-0
  for anything under a `templates/` directory.
- Deliberately not done: no module exists yet, and no check has been written.
  The records describe a process for building a catalog that does not exist.

## Risks

The decision log is written before the decisions have been tested against
anything. Several entries will turn out to be wrong, which is what append-only
is for — but an entry written speculatively and an entry written from experience
read identically, and nothing in the file distinguishes them. Accepted for now;
if it becomes a problem the fix is a marker on speculative entries rather than a
rewrite.
