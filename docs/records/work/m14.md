# M14 — The adoption record says what was reviewed

**Depends on:** nothing.
**Discharges:** `F18` in [findings.md](../findings.md).

Every module in [strucgu.yaml](../../../strucgu.yaml) is pinned `0.1.0` while the
modules ship `0.2.1` to `0.4.0`, so every module section of the
[0.2.0 self-walk](../self-walk-0.2.0.md) emits a drift notice. A pin is a dated
claim about what an adopter reviewed, and the release walk *is* that review,
performed against every module at its shipped version. This repository is holding
a review its own pin says it has not done.

## Done means

- Each of the five pins in [strucgu.yaml](../../../strucgu.yaml) names the version
  that module actually ships, and carries a dated comment naming the review that
  moved it — the [0.2.0 release walk](../self-walk-0.2.0.md), not this unit.
- The self-walk is re-run after the change and the drift notices are gone. If any
  check result moves as a consequence, the unit stops and says so before
  continuing: a pin does not constrain what runs, so a moved result means
  something else was wrong.
- The fixture-tree pins under `modules/*/fixtures/` **do not move**, and the unit
  records that this was checked rather than assumed. Leaving them behind is
  argued in
  [decisions.md](../decisions.md#the-modules-bump-to-020-and-no-adoption-record-moves-with-them),
  and that argument names the fixture trees specifically — which is why `F18`
  exists at all, because the argument was read as covering this file too.
- `F18` moves to *Closed* with its disposition, per the queue's own rule.

## Risks

Low, and the one risk is the interesting part. If moving a pin changes a check
result, the pin was doing work it is documented not to do — a checker evaluates
the module as it reads it, per [SPEC.md](../../../SPEC.md#versioning) — and that
would be a finding against the specification rather than a defect in this file.
It is worth watching for precisely because nobody expects it.

The second-order risk is that this reads as maintenance and gets done without
thought. It is the only file in this repository that makes a claim on behalf of
an adopter, and the claim it makes is about what a human reviewed.
