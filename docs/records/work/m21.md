# M21 — The release is walked, and what moved is stated for an implementer

**Depends on:** [M20](m20.md), hard, and through it everything before it. A guide
defect found after the release is a guide defect the next adopter reads.
**Discharges:** nothing in the queue. It exists because a phase that changes the
contract and does not publish what changed leaves every implementer to diff it —
and because **this release is the one LinkCtrl transitions onto.**

Phase two ended this way and this unit is its equivalent. Two things are
different: the version is the first sized by the rule [M15](m15.md) writes, and
there is a known adopter waiting on the other side of the tag.

## Done means

- Every gate in [triage.md](../triage.md) "Before a release is tagged" over the
  whole repository rather than the changed files, and the repeat-from-step-one
  rule honoured if the walk triggers work.
- **The walk is committed as a third file**, beside
  [self-walk.md](../self-walk.md) and [self-walk-0.2.0.md](../self-walk-0.2.0.md)
  rather than over either. The diff between walks is the only thing here that
  shows movement, and this is the first walk where the fixture count itself moved.
- **The version is sized by [M15](m15.md)'s rule and this is its first use.** If
  the new rule and the two existing ones disagree, the disagreement is reported
  rather than resolved by picking, per the standing answer on
  [the two rules that already measure different readers](../decisions.md#the-two-versioning-rules-measure-different-readers-and-the-conflict-is-reported-rather-than-picked).
- [CHANGELOG.md](../../../CHANGELOG.md) says what an **implementer** must re-read
  and re-run, separately from what an adopter newly sees. Those are different
  lists this time and the entry does not merge them.
- **What an adopter needs in order to start is stated in the release, not only in
  the guide.** The changelog names the module versions to pin, and says that the
  adoption questions [M20](m20.md) answered are answered — because the next reader
  of this entry is somebody deciding whether to begin.
- [README.md](../../../README.md) "What 0.x means here" is rewritten against what
  this phase measured: how many normative statements had no tree, how many now do,
  how many survive with none, and what the deliberate-breakage re-measurement
  returned. **If the breakage number did not improve, it leads.** The count of
  adoptions does not move — nobody adopted during this phase.
- The documentation pass runs over every file, including
  [conformance.md](../../conformance.md), whose *what a claim cannot cover* table
  is the thing [M16](m16.md) spent the phase shortening. A table still listing
  something now pinned is a failing gate.
- **The repository is not tagged by this unit.** Tagging is the owner's action,
  for the reason [M7](m7.md) gives and [M13](m13.md) repeats. The phase ends at
  the walk; the tag and whatever follows it are the owner's.

## Risks

The phase's own results are the risk. This release can be read as the catalog
becoming trustworthy, and what it actually is is a catalog that has measured how
much of itself was untested and found the answer unflattering. The `0.x` section
has to carry that without either apologising or flattering, and it is the third
release running where the honest number is the awkward one.

A quieter risk arrives with the known adopter. Writing a release entry while
somebody specific is waiting to transition onto it pulls toward reassurance —
toward saying the path is ready rather than that every question anyone found has
an answer. [M20](m20.md) states that limit and this unit must not restate it more
warmly.

The changelog now has two audiences with different lists, and the temptation is
to write one list and label it twice. An adopter reading an implementer's list
concludes their repository needs work it does not need.
