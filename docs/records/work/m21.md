# M21 — LinkCtrl adopts, and the walk says what a source repository cannot prove

**Depends on:** [M20](m20.md), hard. An adoption record pins a version, so there
has to be a released one to pin. It also depends on a prerequisite this
repository does not control — see *Risks*.
**Discharges:** the third adoption of this catalog, and the verifiability
deviation [M11](m11.md) took knowingly.

LinkCtrl is the repository these conventions were extracted from. It adopting the
catalog closes a loop, and the first thing this unit has to do is say plainly
what that loop is not: **it is not a third data point.** A clean map here is
guaranteed by construction, because the rules were written by reading this
repository. The value is elsewhere, and it is specific.

## Why it is worth doing anyway

**It is verifiable.** [M11](m11.md)'s second repository is private, so its walk is
redacted and a reader cannot check it — a knowing deviation from this
repository's own release gate, named at the gate. LinkCtrl is public. This walk
can quote every path and every line, and it is the first adoption record here
that an outsider can reproduce.

**LinkCtrl has moved since the extraction.** It now keeps record types this
catalog has never seen: a tracker for changes to its own process, a file of
questions with no answer yet, and a measurement of what its always-read documents
cost to read. None has a role. If the catalog cannot reach the records of the one
repository it was extracted from, that is worth knowing and it is not an
argument, it is a run.

**It makes `F9` concrete.** `F9` says no role reaches a repository's scope
contract unless that repository also has units of work, and notes that this
repository hides the gap from itself because [README.md](README.md) is both its
scope contract and its unit index. **LinkCtrl separates them** — its scope
contract is one file and its unit index is another — so the coupling stops being
an argument and becomes an observation about a public tree.

## Done means

- An adoption record exists at LinkCtrl's root, pinning the versions
  [M20](m20.md) released, and every role it maps is mapped to a path that exists:
  the process document, the decision log and its index, the deferral destination,
  the unit directory, index and template, and the investigations directory.
- **`effective_from` is chosen and argued rather than defaulted**, against a
  repository with real history and real removals — unlike this one, where the
  first commit made the question free.
- **The unmapped list is the unit's primary output**, not the check results. Every
  record LinkCtrl keeps that no role reaches is named, with what it is for and
  whether the catalog should be able to see it. Each becomes a row in
  [findings.md](../findings.md); none is fixed here, because growing the catalog
  is out of scope for this phase and is a decision of its own.
- **The one-process-document assumption is tested.** `triage_doc` is a single
  role and LinkCtrl's process is three documents with a stated precedence between
  them — gates, sequence, and intake. Whichever way that resolves, it resolves on
  the record: one file is mapped and the others are invisible, or the role does
  not fit and that is a finding.
- The audit is run with the checker [M18](m18.md) pulled up, and its output is
  recorded in full — states, counts, and every judgment line — in a walk record
  beside the two self-walks and [M11](m11.md)'s.
- Findings against **LinkCtrl** are LinkCtrl's to fix or to object to, through
  [objections.md](../../objections.md) like any adopter. This unit does not fix
  them and does not treat the objection channel differently because it happens to
  know the adopter.
- **What this adoption is worth is stated where the results are.**
  [README.md](../../../README.md) says two data points, both adjacent to the
  author. This is a third and it is the most adjacent one available, so the
  sentence has to get more careful rather than shorter. The generality question is
  untouched and the unit says so about itself.
- **Nothing is built for LinkCtrl to run this repeatedly.** No action, no
  template, no bot, no CI integration ships from here — that refusal is unchanged.
  If LinkCtrl wants the audit on a schedule it builds that itself out of
  [strucgu-check](https://github.com/DevOfPie/strucgu-check), which is a
  consumer's choice and not this catalog's business.

## Risks

**The prerequisite is outside this repository.** The adoption record is a commit
in LinkCtrl, and LinkCtrl has its own process for placing work — absence
established, phase decided, artifacts written — and its own build loop, which
runs unattended. This unit cannot schedule that, and starting it while that loop
is mid-phase is how two sessions collide in one tree. **The owner places it
there; this unit waits.**

**The result will read as maturity and it is the weakest evidence of the three.**
A second repository sharing a convention lineage was already the expected-clean
case; the extraction source is the guaranteed-clean case. If the walk reports a
clean map and the record does not lead with why that was inevitable, this
repository will have published its most persuasive-looking and least informative
result.

**An empty unmapped list would be the alarming outcome.** The catalog covers five
record types and LinkCtrl keeps at least three more. If the walk finds nothing
uncovered, the walk did not look — and that is the failure mode to watch for,
because it is indistinguishable from success in every mechanical output the run
produces.
