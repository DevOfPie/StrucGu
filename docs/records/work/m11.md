# M11 — The second repository adopts, and every finding is disposed of by the rule

**Depends on:** [M10](m10.md) — an adoption with nothing to run against produces
opinions rather than findings.
**Discharges:** the [README.md](../../../README.md) statement that "one instance
is not enough to know which conventions are general and which are one project's
habits wearing a rule's clothing", **partially and in one direction only.**

The second repository is chosen and is private. **It is not named here**, and it
is not described here beyond what this unit needs to be actionable. The reasoning
is in
[decisions.md](../decisions.md#the-second-repository-is-private-and-it-tests-re-application-rather-than-generality)
and is not restated.

Two facts govern the unit. It is not the repository this catalog was extracted
from, and its own records already commit it to migrating its process rules here —
so adoption is the first step of something it chose, not an exercise staged to
produce a result. And it shares a convention lineage with
[LinkCtrl](https://github.com/DevOfPie/LinkCtrl), which is where these modules
came from.

## What this is not a test of

**A clean map is the expected outcome and is not evidence of generality.** This
tests whether the extraction survives re-application within one convention
lineage. The generality question needs a repository built by someone who has
never read LinkCtrl, and this unit does not answer it. [M13](m13.md) must not
report it as though it did.

It follows that **no objection is the uninformative case, not the suspicious
one.** A clean run is what both an honest audit and an audit that looked away
would produce here, so the observation distinguishes nothing and the evidence
weighs less. An earlier version of this record inferred the opposite and used it
to require an objection be filed; that inference was backwards and the
requirement is gone.

## Done means

- The second repository carries a real hand-edited `strucgu.yaml` mapping its own
  paths — its decision log, its plan, its process file, and whatever plays the
  findings role — with any role it genuinely lacks left unmapped and commented,
  not invented to make the file look complete.
- [M10](m10.md)'s checker is run against it and the output is recorded here,
  redacted of paths and quoted lines that would publish that repository's
  contents. **A redacted result is labelled as one**, rather than presented as
  though the evidence were open.
- **Every finding is disposed of as exactly one of: fixed, waived with a reason
  in that repository's own adoption record, or filed as an objection** carrying
  the six required fields in [objections.md](../../objections.md). "Not really a
  problem" is not one of the three. This is what forces the objection channel
  when a genuine disagreement exists — **and no number of objections is
  required.** A quota for disagreement manufactures disagreement, and
  [objections.md](../../objections.md) makes cost the filter: an objection filed
  to satisfy a done bullet has manufactured cost by construction.
- Any objection is disposed of through the four outcomes in
  [objections.md](../../objections.md) and lands as a dated entry in
  [decisions.md](../decisions.md), including a decline.
- **The catalog's gaps are recorded, not only the repository's.** Where that
  repository keeps a record this catalog has no role for, the gap is a row in
  [findings.md](../findings.md) saying which it is — out of scope for a catalog
  about records of work, or a module this catalog is missing. The row names the
  gap in the catalog's own vocabulary and does not reproduce that repository's
  structure here. This is the more valuable half of the unit's output, and it
  produces rows, not modules — see [work/README.md](README.md) "Not in this
  phase".
- **LinkCtrl is not modified**, not for extraction and not to add a reference.
  That migration and its timing are reserved to its owner. **Attested, not
  verifiable from here** — it is a claim about a third repository.
- Deliberately not done: no attempt to recruit an outside adopter. That is not a
  work unit, it has no falsifiable done condition, and a catalog that measures
  itself by adopters has started counting the thing it refused to count.

## Risks

The audit may be performed to pass. One author's repository, audited with that
author's checker against that author's specification, offers three chances to
unconsciously look away. The mitigation is the disposal rule above — every
finding fixed, waived in writing, or argued — and it is a weak mitigation
against a party who simply does not look hard.

**This unit's committed output deviates from a release gate, knowingly.**
[triage.md](../triage.md) requires every documented claim to be verifiable by a
reader who does not trust you. A redacted audit of a repository that reader
cannot see is not. The deviation is confined to this record, it is argued in
[decisions.md](../decisions.md), and [M13](m13.md) records it at the gate rather
than letting the walk pass silently over it. Naming it is the rule
[triage.md](../triage.md) states for a conflict between governing documents: a
bug to report, not a choice to make quietly.

**Redaction and evidence pull against each other, and redaction wins here.** The
published output is therefore weaker evidence than an equivalent run on a public
repository, deliberately — see [investigations](../../../modules/investigations/)
on conclusions without re-examinable evidence.

The process that repository describes has not been run yet. Its records describe
a workflow with almost no history behind it: the roles will map because the files
were written to be mappable, and the checks will pass over documents that have
barely been exercised. `DL-03` in particular remains unexercised, exactly as it
was in [self-walk.md](../self-walk.md), because there is still no history to
read. That limit belongs in the recorded output.
