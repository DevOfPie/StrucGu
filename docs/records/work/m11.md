# M11 — The second repository adopts, and the objection channel is used in anger

**Depends on:** [M10](m10.md) — an adoption with nothing to run against produces
opinions rather than findings.
**Discharges:** the [README.md](../../../README.md) statement that "one instance
is not enough to know which conventions are general and which are one project's
habits wearing a rule's clothing", **partially and in one direction only.** What
it discharges and what it does not are separated below, because a unit that
claimed the whole thing would be the first false claim in this repository.

The second repository is chosen and is private. **It is not named here**, and the
reason is the rule this catalog already states: audit output and adoption records
carry paths, internal names, and quoted lines, and a public repository is not
where a private one's shape gets published as a side effect of planning. The
owner's records name it. See
[decisions.md](../decisions.md#the-second-repository-is-private-and-it-tests-re-application-rather-than-generality).

It is not the repository this catalog was extracted from. Its own decision log
already names StrucGu as the intended canonical home for its process rules and
records those rules as provisional, written to be lifted out later. So this is
not a staged audit arranged to produce a result — it is a migration that
repository has already decided on, and adoption is the first step of it.

## What this is not a test of

The second repository imported its process conventions from
[LinkCtrl](https://github.com/DevOfPie/LinkCtrl) deliberately, and says so in its
own records: the three-file split with explicit precedence, the terse
trigger-first process file, and the in-spec/out-of-spec deferred-findings
discipline. LinkCtrl is the repository this catalog was extracted from.

**So a clean map is the expected outcome and is not evidence of generality.** It
tests whether the extraction survives re-application within one convention
lineage — real, worth knowing, and a different claim. The generality question
needs a repository built by someone who has never read LinkCtrl, and this unit
does not answer it. [M13](m13.md) must not report it as though it did.

## Done means

- The second repository carries a real hand-edited `strucgu.yaml` mapping its own
  paths — its decision log, its plan, its process file, and whatever plays the
  findings role — with any role it genuinely lacks left unmapped and commented,
  not invented to make the file look complete.
- [M10](m10.md)'s checker is run against it and the output is recorded here,
  redacted of paths and quoted lines that would publish that repository's
  contents. **A redacted result that cannot be checked by a reader is stated as
  such**, rather than presented as though the evidence were open.
- Every finding is disposed of as exactly one of: fixed, waived with a reason in
  that repository's own adoption record, or filed as an objection carrying the
  six required fields in [objections.md](../../objections.md).
- **The catalog's gaps are recorded, not only the repository's.** The second
  repository has record shapes this catalog has no role for — an intake, a
  disposal path, a promotion bar, a staleness sweep. Each one is either out of
  scope for a catalog about records of work, or a module this catalog is
  missing, and saying which is the more valuable half of this unit's output.
  That output is rows in [findings.md](../findings.md), not new modules — see
  [work/README.md](README.md) "Not in this phase".
- **At least one objection is filed, or the absence of one is recorded as a
  finding about this unit.** A second repository that produces no disagreement
  was audited without conviction, and with a shared convention lineage the odds
  of a genuinely clean run are higher — which makes the absence more suspicious
  here, not less.
- Any objection is disposed of through the four outcomes in
  [objections.md](../../objections.md) and lands as a dated entry in
  [decisions.md](../decisions.md), including a decline.
- **LinkCtrl is not modified**, not for extraction and not to add a reference.
  The second repository's own records reserve that migration and its timing to
  its owner, and this phase has no business doing it from the side.
- Deliberately not done: no attempt to recruit an outside adopter. That is not a
  work unit, it has no falsifiable done condition, and a catalog that measures
  itself by adopters has started counting the thing it refused to count.

## Risks

The audit may be performed to pass. One author's repository, audited with that
author's checker against that author's specification, offers three chances to
unconsciously look away. The mitigation is disposing of findings by the rule
rather than by judgment — fixed, waived in writing, or argued in an objection,
and "not really a problem" is not one of the three.

**Redaction and evidence pull against each other, and redaction wins here.** A
finding whose location and quoted line are withheld is a claim a reader cannot
verify, which is the shape this catalog refuses everywhere else — see
[investigations](../../../modules/investigations/) on conclusions without
re-examinable evidence. The published output of this unit is therefore weaker
evidence than an equivalent run on a public repository, deliberately, and the
record says so rather than letting a thin write-up read as a thorough one.

The process the second repository describes has not been run yet. Its records
describe a workflow with almost no history behind it: the roles will map because
the files were written to be mappable, and the checks will pass over documents
that have barely been exercised. `DL-03` in particular remains unexercised,
exactly as it was in [self-walk.md](../self-walk.md), because there is still no
history to read. That limit belongs in the recorded output.

It is private, which brings the exfiltration surface
[objections.md](../../objections.md) names. Any objection filed from it is
written by hand and reviewed before it leaves. This is the first occasion to
actually follow that rule rather than only specify it.
